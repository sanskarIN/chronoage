# ChronoAge 2.0.12

Release date: 2026-08-19

## Status

The repository source and runtime metadata are set to **2.0.12**. The matching semantic tag is `v2.0.12`.

This document describes the 2.0.12 source release. It does not claim that the GitHub tag/release artifact has been published. Tagging remains gated on the reproducible-install, clean release-run, and branch-protection requirements documented in [release.md](../release.md) and [ROADMAP.md](../../ROADMAP.md).

## Highlights

- Privacy-first age, birthday, interval, difference, and milestone calculations remain fully local.
- Optional time-of-day calculations support browser-provided IANA timezones, DST gap rejection, and explicit repeated-time disambiguation.
- Saved profiles support validated local persistence, editing, search, deterministic sorting, bounded progressive rendering, one-step delete undo, import/export, replacement confirmation, and direct Age-calculator handoff.
- Saved-profile validation now rejects impossible timestamp histories where `updatedAt` precedes `createdAt`.
- Page deep links contain only public route identifiers; calculation inputs and saved-profile values are not serialized into URLs.
- SPA route changes update the document title and transfer focus into main content.
- PWA installation, update checks, controlled update application, and offline navigation behavior are covered by browser tests.
- Accessibility automation includes desktop/mobile coverage plus maintained axe WCAG A/AA audits.
- Release-candidate screenshots, structured privacy-safe diagnostics, browser security invariants, metadata checks, documentation-link checks, and gzip bundle budgets are part of the quality toolchain.
- Permanent CI and release workflows use the exact Node.js `22.13.0` project pin.

## Compatibility and data

- Saved-profile storage remains `schemaVersion: 1`.
- No localStorage migration is required for valid existing data.
- ChronoAge remains client-only with no backend/database migration.
- The supported desktop delivery remains the installable PWA; native wrapper work remains intentionally deferred pending a concrete native-only requirement.

## Quality and security boundaries

ChronoAge 2.0.12 keeps the existing layered verification model:

- formatting and metadata checks;
- static browser-security invariants;
- lint and TypeScript checks;
- unit, property, storage, component, and hook tests;
- production build and gzip budget checks;
- Playwright desktop/mobile journeys;
- offline service-worker regression coverage;
- axe WCAG A/AA automated audits;
- CodeQL and dependency review workflows;
- runtime dependency audit in release verification.

## Remaining release gates

The following are intentionally **not** marked complete without real evidence:

1. Generate and review a registry-resolved `package-lock.json`.
2. Migrate permanent CI/release installation to `npm ci` only after that lockfile is accepted.
3. Record a passing clean-checkout quality + E2E + accessibility + offline-PWA + bundle-budget release run using the reproducible install.
4. Enable and verify the documented `main` branch protection/ruleset in GitHub repository settings.

Additional locale packs are separately gated on human translation review. A native desktop wrapper is an intentional product deferral, not a missing 2.0.12 implementation.

## Release identity

Before publishing the tag, verify:

```bash
npm run metadata:check
npm run release:check -- v2.0.12
```

The release workflow must reject any tag that does not match the package/runtime version exactly.
