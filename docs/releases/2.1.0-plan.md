# ChronoAge 2.1.0 — Next-Version Engineering Plan

ChronoAge `2.1.0` is the next planned product milestone after the `2.0.13` release-hardening cycle. This document is a planning artifact only; an item is not complete until implementation and direct verification exist on the repository.

## Primary goals

1. Finish reproducible dependency installation with genuine npm and Cargo lockfiles.
2. Make web, E2E, and Native CI deterministic and lockfile-first.
3. Establish effective `main` branch governance with required checks.
4. Improve internationalization from English-first architecture to the first reviewed locale pack.
5. Improve backup compatibility and diagnostics without changing the privacy-first local-only model.
6. Produce stronger release-candidate evidence before any public platform artifact is declared ready.

## Release gates

### Dependency reproducibility

- [ ] Generate and review `package-lock.json` using the pinned Node.js `22.13.0` runtime.
- [ ] Generate and review `src-tauri/Cargo.lock` using the pinned Rust `1.97.1` toolchain.
- [ ] Verify both lockfiles with the repository lockfile preflight scripts.
- [ ] Confirm clean `npm ci` installation from a fresh checkout.
- [ ] Confirm native Cargo verification uses locked dependency resolution where required.

### Continuous integration

- [ ] Replace permanent push/PR CI frontend `npm install` with `npm ci`.
- [ ] Replace Native CI frontend `npm install` with `npm ci`.
- [ ] Keep release CI on the same lockfile-first installation policy.
- [ ] Add regression coverage so permanent workflows cannot silently return to mutable dependency installation.
- [ ] Record a completely green web and Native CI release-candidate matrix.

### Repository governance

- [ ] Configure the documented `main` branch protection/ruleset.
- [ ] Require the relevant web, security, and native checks before merging.
- [ ] Disable force-push and branch deletion for `main`.
- [ ] Verify the effective repository configuration through GitHub after applying it.

### Internationalization

- [ ] Complete translation review for one additional locale.
- [ ] Add locale selection without putting private calculator/profile data into URLs.
- [ ] Add locale-specific formatting tests for dates, numbers, weekdays, and duration labels.
- [ ] Keep English as the fallback locale when a translation key is unavailable.

### Backup compatibility

- [ ] Add explicit backup schema version metadata for future migrations.
- [ ] Preserve current malformed-input and impossible-history rejection behavior.
- [ ] Add forward-compatibility handling that reports unsupported future schemas safely.
- [ ] Expand round-trip tests for export/import replacement and profile history timestamps.

### Release evidence

- [ ] Keep deterministic archive, checksum, and machine-readable manifest generation intact.
- [ ] Bind release evidence to the exact source commit and package version.
- [ ] Re-run the clean-checkout web/E2E/native gates for the exact release candidate.
- [ ] Treat signing, notarization, and store publication as separate credential-dependent gates.

## Non-goals for 2.1.0

- No backend or account system.
- No analytics or mandatory telemetry.
- No cloud synchronization.
- No encryption claim for exported JSON backups unless encryption is implemented and independently reviewed.
- No platform-store publication claim without target-platform build and signing evidence.

## Suggested implementation order

1. Genuine npm lockfile.
2. Genuine Cargo lockfile.
3. Permanent CI/native `npm ci` migration.
4. Locked native verification and full hosted matrix.
5. Branch protection/ruleset verification.
6. Backup schema-version groundwork.
7. First reviewed locale pack.
8. Final 2.1.0 release-evidence run.

The order intentionally puts reproducibility and governance ahead of user-facing expansion so every later feature lands on a deterministic release pipeline.
