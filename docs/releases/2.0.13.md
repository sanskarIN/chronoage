# ChronoAge 2.0.13

Release date: 2026-08-25

## Status

ChronoAge **2.0.13** is the next source-release checkpoint. The matching semantic tag is `v2.0.13`.

This release prepares a stronger web-release evidence chain while preserving the existing privacy-first product behavior and cross-platform Tauri 2 delivery architecture. It does not claim that `v2.0.13` has been tagged or published, that hosted CI is green, or that signed native artifacts exist. Publication remains gated on the explicit reproducibility and release-evidence requirements below.

## Highlights

- Adds a deterministic machine-readable release evidence manifest for the verified web archive.
- Records the exact package version, release tag, full source commit, commit-derived source-date epoch, Node runtime, archive size, archive SHA-256, and generated dependency-lock hashes when present.
- Refuses to generate release evidence when the semantic tag drifts from `package.json`, the commit SHA is abbreviated/invalid, the source-date epoch is invalid, or the checksum does not match the release archive.
- Re-verifies the downloaded archive checksum in the publish job before GitHub Release creation.
- Publishes the archive, SHA-256 checksum, and evidence manifest together.
- Extends the static release-workflow policy gate and regression coverage so checksum verification, evidence generation, and manifest publication cannot be removed silently.
- Keeps deterministic tar ordering, normalized timestamps/ownership, `gzip -n`, lockfile-only release installation, verified-tag publication, and verify-before-publish ordering.

## Compatibility and data

- No user-data migration is required.
- Saved-profile storage remains `schemaVersion: 1`.
- ChronoAge remains local-first/client-only; release evidence contains build/release metadata, not user data.
- Web/PWA, Windows, macOS, Linux, Android, and iOS/iPadOS remain supported from the shared React + TypeScript + Tauri 2 source architecture.
- The native identifier remains `in.sanskar.chronoage`.

## Release evidence files

A successful tag release is expected to publish these sibling files:

```text
chronoage-web-v2.0.13.tar.gz
chronoage-web-v2.0.13.tar.gz.sha256
chronoage-web-v2.0.13.manifest.json
```

The manifest is generated only after the archive checksum exists and has been independently matched against a fresh SHA-256 digest of the archive. The publish job then runs `sha256sum --check` again after artifact download and before creating the GitHub Release.

## Remaining release gates

The following remain intentionally incomplete until real external evidence exists:

1. Generate and review a genuine registry-resolved `package-lock.json` using the pinned Node toolchain.
2. Prove a clean `npm ci` installation and then migrate permanent push/PR and Native CI frontend installation from `npm install` to `npm ci`.
3. Generate and review a genuine `src-tauri/Cargo.lock` using Rust `1.97.1` and use Cargo `--locked` where release/native resolution drift must be forbidden.
4. Run and record passing clean-checkout `npm run check`, Playwright E2E, `npm run native:check`, and the complete hosted Native CI matrix.
5. Enable and verify effective `main` branch protection/rulesets.
6. Produce signed/notarized/store-ready native artifacts only when the required release accounts, signing identities, and secrets are configured.

Neither dependency lockfile should be hand-authored or guessed.

## Release identity checks

Before tagging, verify the synchronized source version and release tag:

```bash
npm run metadata:check
npm run release:check -- v2.0.13
npm run release:workflow:check
```

When real dependency lockfiles have been generated and accepted, also run:

```bash
npm run release:locks:check
npm run check
npm run test:e2e
npm run native:check
```

A source commit, local syntax check, or successful repository write is not equivalent to a passing hosted release candidate.
