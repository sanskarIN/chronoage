# ChronoAge 2.0.13

Release date: 2026-08-24

## Status

The release-preparation branch aligns source/runtime/native metadata to **2.0.13**. The matching semantic tag is `v2.0.13`.

This document describes the 2.0.13 source release candidate. It does not claim that the GitHub tag, signed native installers, notarized packages, or store artifacts have already been published. Publication remains evidence-gated by the reproducible dependency state, clean hosted quality runs, native matrix results, and repository protection requirements documented in [release.md](../release.md) and [ROADMAP.md](../../ROADMAP.md).

## Highlights

- Tauri 2 delivery now covers Windows, macOS, Linux, Android, and iOS/iPadOS while reusing the same React + TypeScript frontend and date-domain implementation as the web/PWA build.
- Browser-only PWA installation and service-worker update behavior is disabled inside installed native runtimes.
- Native permissions remain least-privilege with the `core:default` capability only.
- Native CI covers desktop compile targets, Android debug APK smoke builds, and iOS simulator smoke builds.
- Release engineering includes explicit npm/Cargo lockfile preflight checks and regression coverage.
- Tag releases require a valid npm lockfile and use `npm ci` rather than an unpinned install fallback.
- Web release archives use deterministic entry ordering, timestamps, ownership metadata, gzip metadata suppression, and SHA-256 checksums.
- A static release-workflow policy check protects reproducibility and verify-before-publish safeguards from accidental regression.
- Security, native delivery, mobile/desktop setup, and reproducible-build documentation now match the implemented architecture.

## Compatibility and data

- Saved-profile storage remains `schemaVersion: 1`.
- No localStorage or user-data migration is required for valid existing data.
- The application remains client-only; native shells do not introduce a backend, cloud account, or remote profile database.
- Web/PWA, Windows, macOS, Linux, Android, and iOS/iPadOS remain supported from one shared codebase.

## Reproducibility boundary

The 2.0.13 release candidate is specifically hardening reproducible dependency and build behavior.

A genuine `package-lock.json` and `src-tauri/Cargo.lock` must come from successful registry resolution using the pinned toolchains. They must not be hand-authored or inferred. Permanent CI/native migration to lockfile-only installation and Cargo `--locked` verification is accepted only after those generated dependency graphs are reviewed and validated.

## Quality and security boundaries

The release candidate retains the existing layered verification model:

- formatting, metadata, compatibility, GitHub Actions policy, release-workflow policy, and static security checks;
- lint and TypeScript checks;
- unit, property, storage, component, and hook tests with coverage;
- production build and gzip bundle-budget checks;
- Playwright desktop/mobile journeys, offline-PWA coverage, accessibility audits, and release-candidate screenshots;
- Rust formatting, clippy, native compile validation, Android smoke build, and iOS simulator smoke build;
- CodeQL, dependency review, and runtime dependency audit gates.

## Remaining publication gates

The following remain evidence-gated until the repository or hosted workflows prove them complete:

1. Review and accept registry-generated npm and Cargo lockfiles for the exact 2.0.13 dependency graph.
2. Verify clean `npm ci` plus the complete web quality/E2E suite from the accepted lockfile.
3. Verify Cargo `--locked` checks and the complete hosted Native CI matrix.
4. Enable and verify the documented `main` branch protection/ruleset.
5. Produce, sign, notarize where applicable, verify, and publish native installers/store artifacts only when platform credentials are configured.

Additional locale packs remain separately gated on complete human translation review.

## Release identity

Before publishing the tag, verify:

```bash
npm run metadata:check
npm run release:locks:check
npm run release:check -- v2.0.13
```

The release workflow must reject a tag that does not match the package/runtime/native version exactly or that lacks the required reproducible npm dependency state.
